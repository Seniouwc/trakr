# trakr vs Renoise: parity report

Scores are out of 10 and mean "how much of what a Renoise 3.x user relies on in this area works in trakr
today", not code quality. **Caveat:** the reference is my memory of Renoise 3.x behavior, not the official
manual or a side-by-side session, so treat scores as informed estimates. Command ids and `.xrns` element
names are unverified (see `docs/PARITY.md`, which lists every item).

Evidence base: about 30,000 lines of Rust in 17 crates and 283 automated tests (last full run green, clippy clean) (engine rendering and fuzzing,
editor operations and fuzzing, GUI input routing, file formats, a real CLAP test plugin loaded from disk,
sandboxed Lua). The GUI was driven live under a virtual display. **Not tested:**
real speakers or audio devices (device/host/buffer switching is only tested with a fake backend; JACK was never built), real third-party plugins and plugin windows, recording from a real microphone, a real MIDI keyboard, Windows/macOS, long
sessions, large songs.

## Scorecard

| Area | Score | Where it stands |
|---|---|---|
| Pattern editor and note entry | 6.5 | Notes, instrument, volume, pan, delay, effect columns; hex entry; selection, copy/cut/paste, transpose, reverse, interpolate, fade ramps, insert/delete line; unlimited-ish undo; add/remove tracks and columns; MIDI recording. Phrase editor (Phrases dock) and Lua scripts for bulk edits. Find/replace, randomize, expand/shrink/repeat block and a command palette. Missing: per-sub-column visibility, mix and flood paste, line highlight settings, track colors/groups/collapse. |
| Song structure and sequencing | 6.8 | Sequence list (insert, clone, delete, move, pick pattern), pattern length and names, loop range, play song / pattern / from cursor, follow. Pattern matrix, named sections, per-slot track mutes, groove/shuffle, loop-a-block and song properties. Missing: tempo/LPB automation lanes, section-level repeat counts, matrix drag-and-drop of patterns. |
| Effect commands | 4.3 | The core set (track volume/pan, note volume, maybe, stop track, ticks per line; tempo, break, sample offset, backwards, cut, delay, retrigger, pitch slides, glide, vibrato, tremolo, arpeggio, volume slide, fade in/out). Volume and pan columns work on notes and running notes. Missing: special volume-column commands, envelope control, track width, effects on delayed notes, ghost notes, most of the Z set. |
| Instruments and playback | 7.6 | Multiple samples per instrument with key and velocity zones, NNA modes, base note and fine tune, forward/reverse/ping-pong loops, volume/pan/pitch/cutoff envelopes with a hold point, per-instrument filter, per-note effects. Phrases (own speed, columns, loop region, key-mapped and transposed). Instruments can also send MIDI notes. Per-note LFOs (volume, pan, pitch, cutoff), key tracking and velocity-to-cutoff. Stepper and smooth-random modulators, key/velocity/macro routings, envelope loops and fade-out. Missing: drive modulation, phrase program mode and shuffle, sample FX chains, oversampling, instrument bank. Sinc playback is band-limited for pitch-ups and CLAP instrument plugins can be an instrument. |
| Sample editor | 7.3 | Zoomable waveform, selection, cut/copy/paste/delete/crop, silence, fades, gain, normalize, invert, DC removal, reverse, mono/stereo, tape pitch shift, resample, slicing with split-to-keys, loop editing, export to WAV/FLAC/Ogg/MP3/AAC/Opus, import of WAV/AIFF/FLAC/OGG/MP3, live recording. | Mixer and DSP | 6.2 | Per-track bus, device chain, fader with mute/solo/off, pan, master chain and volume, meters with peak hold. Thirty-seven native devices (maximizer, analog filter, mid/side, convolver, key/velocity trackers, meta mixer, formula, send marker among them; gainer, filter, ladder filter, 3- and 10-band EQ, gate, compressor, limiter, delay, reverb, chorus/flanger, phaser, distortion, bit crusher, ring mod, stereo width, tremolo/auto-pan, exciter, plus LFO and envelope-follower modulators) against Renoise's roughly fifty, and local CLAP effect plugins. | Automation and modulation | 5.6 | Per-pattern lanes for track volume/pan and any native device parameter with a graph editor and playhead. Plugin parameters can be automated too. LFO and envelope-follower devices drive any parameter in the same chain (control rate, one block of delay). | Plugin hosting | 4.4 | Local CLAP effects and instruments (mono/stereo): scan, add to a track or instrument, sliders, automation, saved with the song (including the plugin's own state), floating plugin windows with host timers and fds, parameter changes made in the window flow back to the sliders, used in offline render; tested against a real shared library with a synth, window, timer and state. Real third-party plugins and windows are untested. Missing: embedded windows, latency compensation, sidechain, VST2/VST3/LV2/AU, sandboxing. |
| MIDI, OSC, scripting | 6.0 | MIDI input for notes, CC7/CC10 and transport; MIDI output per instrument with program change; MIDI clock and start/stop master with a latency setting; sandboxed Lua 5.4 scripting (song, patterns, cells, selection, undoable runs, console, user script folder). MIDI clock input follows an external tempo; MIDI learn maps controllers to faders, device parameters and commands; OSC server for transport, mixer, devices and notes; the Lua API reaches instruments, tracks, devices and automation. Pitch bend is mapped. Missing: OSC feedback/client, script callbacks and menu hooks, sample access from scripts. |
| File formats and project | 5.8 | Native `.trkr` roundtrip, export to WAV/FLAC/Ogg Vorbis/MP3/AAC/Opus with a quality scale up to lossless or the codec maximum, a render rate up to 192 kHz and dither, song bounce to sample, `.xrns` import of metadata, tracks, patterns, notes, sequence and instruments with sample audio (no envelopes, devices or automation; element names and sample paths are from memory and only tested against synthetic fixtures, so real-world files may import differently). Autosave with crash recovery and a recent-files list work. `.xrns` export (metadata, tracks, patterns, sequence, instruments with 24-bit samples; roundtrip-tested through the importer; envelopes, devices, automation, phrases and routing are not exported and are reported). `.s3m` and `.xm` import; backups on save; per-track stem and loop-range export in every format. Missing: `.xrni`/`.xrnt` instrument and preset formats, IT import (MOD, S3M and XM work), per-pattern render, tags/metadata, M4A container. |
| Interface and workflow | 6.2 | Native GUI with menus showing shortcuts, context menu, mouse selection, continuous scrolling pattern view, dockable mixer/devices/automation/instrument panels, help window with effect table. | Engine quality and reliability | 5.0 | Real-time-safe design, sample-accurate delay column, tick timing, smoothing against clicks, seeded fuzz tests, CPU/voice meter. Weak spots: 256 voices fixed, 64 track limit, voices free large buffers on the audio thread in rare cases, no PipeWire-native backend, no latency compensation, everything unverified on real hardware. |

## Overall

**About 6.2 / 10 weighted by what a typical Renoise song uses day to day** (pattern editing, instruments,
sample editing, mixing and effects count most; plugins, scripting and format breadth count less). In plain
terms: trakr can already be used to sketch and finish simple sample-based tracker songs on Linux, and its
sample editing and pattern workflow are the closest to Renoise. It cannot yet replace Renoise for anyone who
depends on VST/LV2 plugins or proven third-party CLAP plugins, a full effect rack, or opening existing Renoise projects faithfully.

## Highest-value gaps, in order

1. **Verify `.xrns` import against real files** (instruments and samples are only checked against synthetic fixtures), then add envelopes, devices and automation to it.
2. **Hardware and real-plugin verification pass**: real audio devices, latency, JACK/PipeWire, real MIDI keyboards, real third-party CLAP instruments and windows, long-session soak tests.
3. **Remaining effect commands and special volume/pan column commands**, checked against the manual.
4. **Automation depth**: curves and interpolation modes, recording knob moves, envelope copy/paste, tempo/LPB lanes.
5. **More native devices and general routing** (arbitrary sidechain taps, track delay, plugin delay compensation).
6. **VST3/LV2 hosting and embedded plugin windows.**
7. **Phrase program mode and shuffle, drive modulation, sample FX chains, `.xrni`/`.xrnt` formats.**
8. **Script callbacks and menu hooks, OSC feedback.**
